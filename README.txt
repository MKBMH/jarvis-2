PART A — UPDATE THE EXISTING PUBLIC DASHBOARD
1. Upload ONLY index.html, sw.js and manifest.webmanifest to the root of your existing GitHub repository mkbmh/jarvis-2, replacing those three files. Keep all other assets and the existing backend unchanged.
2. After GitHub Pages finishes deployment, open https://mkbmh.github.io/jarvis-2/?v=15-theone1 in Safari. If an old version appears, test in Private Browsing first. Do not clear stored data.
3. Expect THE ONE PROTOCOL, 84 modules, and /theone in the one-touch directory. Its private portal address is empty until Part B is complete. Never put secrets into the GitHub repository or public JARVIS dashboard.

PART B — DEPLOY YOUR PRIVATE SERVER (Cloudflare account required)
The exact dashboard labels can vary. Use free tiers only if available to you; verify plan limits before continuing. No paid service is required by the source code. Do not replace your existing JARVIS AI Worker.
1. In https://dash.cloudflare.com/ create a NEW Worker, e.g. jarvis-one. Paste the complete private-worker/worker.js into the Worker code editor and deploy. It intentionally returns setup-incomplete until configuration is present. Do NOT upload it into GitHub. It contains no owner credentials.
2. Create a new D1 database, e.g. jarvis-one-private. In its SQL console execute private-worker/schema.sql. Bind the database to the new Worker under the exact binding name DB. Check the SQL console reports success.
3. Set up Cloudflare Zero Trust Access for the new Worker hostname. If the workers.dev access toggle is offered, enable it; otherwise use a supported hostname that you already control and can protect with Access (the dashboard launcher currently accepts only workers.dev URLs; a custom hostname can be opened separately). Do not proceed to private data until this is configured. Create a self-hosted Access application protecting the entire private Worker hostname, including /api/* and assets. Set an Allow policy restricted to your exact personal login email, not an entire domain or Everyone. Disable public Bypass policies. Set an appropriate identity session duration and use an identity provider with strong MFA. Access email OTP is a possible initial provider, not biometric authentication. Configure a passkey-capable provider if available; verify it on your iPhone. This package does not implement its own WebAuthn registration or Face ID enforcement.
4. In the new Worker's settings set variables ACCESS_ISSUER (your exact https://TEAM.cloudflareaccess.com team domain, without path), ACCESS_AUD (the Access application's audience tag), and OWNER_EMAIL (the exact owner login email). Add OWNER_ENROLL_SECRET as an encrypted Worker Secret: generate a new high-entropy random value of 32–128 letters, digits, underscores or hyphens, preferably 43+ random characters. Save in your password manager. Never share it or put it in public code. Deploy the configuration. The server verifies the Access JWT signature, issuer, audience, expiry and exact email independently. The D1 database holds encrypted vault data and hashed random browser-session tokens, not the enrolment secret.
5. Open the private Worker directly in Safari. Complete Access login. The portal should show 'Approve this browser'. Enter a label and your enrolment secret ONLY on your verified private Worker hostname. Set a different, strong vault passphrase (12+ characters) and confirm it when creating the vault. Save a harmless test note, lock, reopen, and confirm recovery. The secret is needed when approving a fresh browser session (12-hour lifetime); revoking a session invalidates its server requests, not the upstream Access login. Synced credentials and browser labels are not hardware-bound device attestation.
6. In the updated public JARVIS, open /theone, enter and save your exact verified HTTPS workers.dev address (root URL ending /), then open your private portal. No credentials are sent from the public site.
7. Test negative access: in a signed-out browser the portal must reject access or require Access sign-in; with a different account it must deny access; a signed-in but unapproved session must be denied /api/vault; after revocation that browser must fail to fetch the vault. Test with dummy data before trusting real records. Rotate OWNER_ENROLL_SECRET if leaked; use emergency lockdown to delete existing sessions, then revoke identity-provider sessions via its dashboard as needed. Already decrypted screens may remain visible until local lock; downloaded copies cannot be recalled.

FEATURES AND LIMITATIONS
- Private owner identity, custom name and greeting; owner approval and revocable browser sessions; searchable encrypted memory; private command templates; local voice greeting; emergency server-session revocation; encrypted legacy instructions; self-issued ECDSA certificate and signature check; on-demand private briefing.
- The owner certificate is self-issued, signed by a fresh key; the signing private key is not retained. It is not proof of legal ownership or a government identity. It verifies against its included key; establish trust in that key independently.
- Passkey / Face ID depends on the configured identity provider and iPhone support. No direct biometric gate is built or tested. Local voice availability depends on the browser. Briefings are on-demand and use owner-entered notes, not an automatic live intelligence service. Private commands are text templates, not unattended execution.
- Vault encrypted client-side using AES-256-GCM, fresh 96-bit IV, 16-byte salt, PBKDF2 SHA-256 600,000 iterations. Server stores only the ciphertext envelope and operational metadata. The portal's JS must still be trusted; a compromised server/administrator could replace it. The vault locks after 3 minutes of inactivity or when hidden. Unsaved edits are discarded. Back up separately with the original vault passphrase; no recovery without it. Existing GitHub local vaults and recordings are not covered.
- No Twilio, paid AI or new paid subscription integration. Existing external apps or backend usage may incur charges. Free-plan availability and quotas are not verified here.
